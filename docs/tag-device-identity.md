# 多块屏幕的蓝牙身份

网关用蓝牙地址生成设备 ID，例如 `da-f55f1de42653`。名称可以重复，蓝牙地址必须能区分每块屏幕。

旧版构建脚本从 `.local/hardware/tag-address.txt` 取出测试板地址并写入镜像。这可以让一块测试板重启后保持身份，但同一个 BIN 烧入其他板后也会复制地址，导致网关只显示一个设备，并可能连接到其中任意一块。

## 0.3.2 修复

构建脚本保留 SDK 配置中的全零占位地址，注册官方 `default_app_generate_unique_static_random_addr` 回调。启动时该回调读取 DA14585 的出厂 OTP 时间戳和测试站信息，生成静态随机蓝牙地址。同一份 BIN 可用于多块正常出厂的芯片；同一块芯片重启和以后升级到沿用此逻辑的固件，地址保持稳定。

此过程只读取 OTP，不编程 OTP，也不靠每次上电随机生成地址。无需逐块编译、输入 MAC 或向 Flash 写入新的身份数据。实现依赖芯片有效的出厂信息，两块实物同时发现需要烧录后验证。

本版保留 0.3.1 的屏幕驱动、刷新策略、时钟和轮播功能。链接布局调整保留区预留空间以容纳地址初始化代码，实际保留数据、BLE 堆和 1536 字节栈容量保持不变。

## 已经烧入相同旧版 BIN

1. 备份工作台数据目录，保留原屏幕的画布和模板。新地址会生成新的设备记录，原设置不会自动迁移。
2. 将两块板分开操作，用 J-Link 和支持该板外部 SPI Flash 的编程器分别安装 `epapers-tag-factory-0.3.2.bin`。两块使用同一个文件即可。
3. 完整镜像写入外部 SPI Flash 偏移 `0x000000`，包含启动程序、应用分区 1、空白分区 2 和 `0x038000` 的产品头。先备份整个外部 Flash，再编程并读回校验；分区 2 也必须处理，避免继续启动旧镜像。
4. 断电重启后，在网页发现屏幕。核对两块地址不同，为其分别配置名称、房间、屏幕型号和画布。
5. 确认两块均可独立更新后，再删除旧地址的残留设备。之后可以用新的 `.img` 统一网页升级。

当前已知两块地址重复时，无法可靠指定无线升级目标，不要同时通电做批量 OTA。升级到本版会改变旧地址，旧版工作台的 OTA 完成核对会尝试重连原地址；本次迁移使用有线安装。

## 文件用途

| 文件 | 用途 |
| --- | --- |
| `epapers-tag-factory-0.3.2.bin` | 外部 SPI Flash 完整安装镜像，233472 字节 |
| `epapers-tag-0.3.2.img` | SUOTA 应用镜像；供已使用独立地址的设备升级 |
| `SHA256SUMS.txt` | 文件完整性校验 |
| `tag-identity-manifest.json` | 构建版本、应用 CRC、内存布局和验证范围 |

J-Flash 的导入地址由具体 Flash 算法决定，不能仅凭文件后缀选择地址。此完整 BIN 不能作为 RAM 应用通过 J-Link Commander `loadbin` 执行。项目 `scripts/install_tag.py` 只支持已经确认空白的 FM25Q04，不支持直接覆盖非空 Flash。

不要用旧版 0.3.0 / 0.3.1 镜像给这些设备回退，它们会恢复内置的重复地址。

## 验证范围

已用 SDK6 的实际地址生成 C 代码，在模拟不同芯片出厂数据的主机测试中验证重启稳定性、不同时间戳与测试站生成不同地址，以及 1000 组不同时间戳不重复。生成配置已核对采用独立地址回调，完整固件构建及镜像 CRC 校验通过。

本次 J-Link 探针连接失败，未对两块实物执行烧录或验证同时发现。已有 A41 屏幕显示和旧版双分区 OTA 的实机结果不能代替本次身份迁移验证。

后续实机验证（2026-10-06）：两块屏幕已运行 0.3.3，分别使用 `D1:B0:51:BC:41:58` 和 `DD:20:88:4A:42:5E`，同时在线，状态读取、电压采样更新和画布下发均收到完成回执。前者从 0.3.2 无线升级到 0.3.3 后地址保持不变。

后者由旧固定地址 `F5:5F:1D:E4:26:53` 无线升级后改为独立地址；网关仍核对原地址，任务在 97% 报连接失败，但重新扫描已读到新地址上的 0.3.3 固件。已手动迁移原画布和设置并删除旧地址记录。工作台尚不支持自动关联这种身份变化，因此首次身份迁移仍按上面的有线步骤逐块操作，不应把任意新发现设备直接认作升级目标。
